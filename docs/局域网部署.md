# SHEIN 选品定价台 —— 局域网部署与运维

> 这台电脑（192.168.31.213）常驻跑一个本地服务，**登录 Windows 后自动启动**，
> 局域网内任何人用浏览器打开 **http://192.168.31.213:8901/** 就能用：
> 粘贴 1688 商品链接 → 自动出变种规格、定价和计算公式。

---

## 1. 访问地址

| 谁 | 地址 |
|---|---|
| 本机 | http://127.0.0.1:8901/ |
| 局域网其他人 | **http://192.168.31.213:8901/** |

服务只监听 8901，数据不出局域网；页面上的计算全部在**访问者自己的浏览器**里完成。

⚠️ 本机 IP 是 DHCP 分配的，路由器重启后可能变。用 `ipconfig` 看 WLAN 的 IPv4，
或看 `logs\server.log` 每次启动打印的那两行地址。

## 2. 首次部署：三步（只需做一次）

1. **放行防火墙**（必须）：双击 `allow-lan-firewall.cmd`，在 UAC 弹窗点「是」。
   不做这一步，局域网其他电脑连不上（浏览器一直转圈）。脚本等价于：
   ```
   netsh advfirewall firewall add rule name="SHEIN选品定价台 8901" dir=in action=allow protocol=TCP localport=8901 profile=any
   ```
2. **装开机自启**：双击 `install-autostart.cmd`。它在
   `%APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup` 里放一个名为
   `SHEIN选品定价台.lnk` 的快捷方式，目标为
   `...\venv\Scripts\pythonw.exe "…\shein-listing\server.py"`。
   登录后静默常驻，**不弹黑窗口**，**不需要管理员权限**。
3. **抓取用哪个浏览器**（两种模式，自动挑）：
   - **模式①（推荐）：你自己的 Chrome**。双击一次 `use-my-chrome.cmd` —— 它要求**先完全退出
     Chrome**（因为 Chrome 只有启动时带 `--remote-debugging-port` 才能被接管），然后带调试端口
     把你的浏览器重开、标签页自动恢复。之后点「读取商品」**只会在你这个浏览器里新开一个标签页**，
     用你自己的登录态与历史，**不弹新窗口、也不用再验证**（你既然在里面登录过 1688，直接就能读）。
     调试端口只监听本机；关掉 Chrome 即失效，想要回原样就正常方式打开 Chrome。
   - **模式②：工具自己的常驻浏览器**（独立配置 `.chrome-profile`，是**另一个窗口**）。
     没跑模式①时用它：第一次抓取自动打开，验证/登录只做一次；窗口**不会因为抓取结束/超时/
     停服务而关闭**；抓取只在里面开标签页（同一链接复用那个标签页）。手动开关：
     `open-browser.cmd` / `close-browser.cmd`。
   - 两种模式都把 cookie 每 8 秒存一份到 `.chrome-cookies.json` 作第二重保险；
     `/api/health` 的 `browser` 字段能看到当前用的是哪种、端口多少。
   规格弹层里"登录查看全部规格"藏起来的颜色，登录后也能一起抓到。

做完三步，双击 `verify-autostart.cmd` 跑一遍自检，四项全绿就算部署完成。

## 3. 常用脚本

## 4. 部署机制（以及为什么这么做）

| 选择 | 原因 |
|---|---|
| 服务监听 `0.0.0.0:8901` | 局域网可访问；想只本机用就把环境变量 `HOST=127.0.0.1` |
| 关掉 `SO_REUSEADDR`（`allow_reuse_address=False`） | Windows 上开着它，**第二个实例也能绑同一端口**，会静默起两份服务；关掉后重复启动会明确报「端口起不来」 |
| 自启用**启动文件夹 + pythonw** | 计划任务（`schtasks /sc onlogon`）需要管理员，本机没有；`wscript.exe` 托管 VBS 在无桌面会话里直接失败；`pythonw.exe` 是无控制台版 Python，登录后静默常驻，最省事也最稳 |
| `.cmd` 包装脚本**只用英文** | cmd 按系统代码页（GBK）解析批处理文件，文件里的 UTF-8 中文会把整行解析搞崩；中文提示一律放在 `.ps1` 里 |
| `.ps1` 一律带 **UTF-8 BOM** | Windows PowerShell 5.1 对无 BOM 的 UTF-8 文件按 GBK 解码，中文会变成语法错误 |
| 服务内部自愈循环 | HTTP 服务异常退出后自动重建（10 秒一次）；整个进程被 kill 则由下次登录或 `serve.cmd` 拉起 |

## 5. 抓取是怎么工作的

- 用**本机安装的 Chrome**（Playwright 驱动，独立用户目录），因为要用本机的 1688 登录态。
- **一个常驻的抓取浏览器窗口**（`tool-browser.cjs`）。两种模式，优先级：**① 你自己的 Chrome**
  （`.use-my-chrome.json` 存在且端口通）→ **② 工具自己的常驻浏览器**（`.tool-browser.json`）。
  无论哪种，抓取端都是 CDP 连上去、只开一个标签页：
  - 人还在过验证码时**窗口不会被关**（抓取成功/超时/换链接/停服务都不关它）；
  - 同一个链接再抓会**复用那个标签页**，你之前的验证、滚动位置都还在；
  - 停服务、重启服务（比如我改完 `server.py`）**都不会关掉它**；
  - 模式①的额外好处：完全在你自己的浏览器里，登录态、插件、历史都在，不用再验证。
  - 端口/pid 记在标记文件里（你自己 Chrome 的记 `.use-my-chrome.json`、工具浏览器的记
    `.tool-browser.json`），`/api/health` 的 `browser` 字段能看当前用的哪种、端口多少。
- 遇到验证码/登录页**不会失败**：页面状态区会亮红提示「请手动拖一下 / 请登录」，
  你处理完它**自动继续**，不用点重试。单次等待上限 30 分钟，到点前 60 秒会在页面上预告
  「还剩 N 秒这次抓取就先放弃」；真到点了也没关系 —— **窗口和标签页都留着**，
  验证完回来点一次「读取商品」就接着用那个页面。
  **发现验证码/登录页时窗口会彻底安静下来**（不再自动截图、不滚动、不移动鼠标），
  免得你拖滑块时被程序抢焦点；此时会落一张 `.last-page.png` 和 `.last-page.txt` 供排查。
- **绝不把验证页当成功**：除了页面文字判据（验证码/登录/拦截关键词），还加了 URL 判据 ——
  只要地址已经跳到 `login.1688 / sec.1688 / punish / verify / captcha` 之类，
  或地址里已经没有这个 offer id，就直接判为「等你验证」，哪怕页面上有价格也不认
  （验证页里的推荐位价格会骗过解析，产出假上架表）。
- **正在过验证/登录时不要停服务**：`stop-service.cmd` 会把这次抓取的 node 进程杀掉
  （浏览器窗口现在能活下来，但那次抓取会被打断）。脚本会先查 `/api/health`：有抓取在跑就
  拒绝停并提示，确认要停再加 `-Force`。改完 `server.py` 重启也请避开抓取时刻。
- **对 1688 客气一点（重要，避免被弹保护验证）**：
  1. **同一链接 30 分钟内直接用缓存**，不再访问 1688（状态区会写明「用的是 N 分钟前的缓存」）；
     要硬拉最新数据就勾「强制重新抓（忽略缓存）」。
  2. 两次**真正访问**之间最少间隔 45 秒（新链接会被拦下并提示还剩几秒）；
     同一链接走缓存不受这个限制。
  3. **同时只允许一个抓取**，不会开两个浏览器窗口。
  4. 抓取端做了拟人化：新访客先落到 1688 首页逛一下再带 Referer 点进商品页，
     等待时间随机抖动（不是固定的 2 秒），到位后先滚动/移动鼠标再读内容。
  - 上面三个数字都在 `server.py` 顶部：`CACHE_TTL`（默认 1800 秒）、`FETCH_COOLDOWN`（默认 45 秒）。
- 弹窗是**真实窗口大小**：抓取端用的是 `viewport: null`（页面跟随窗口与系统缩放，
  本机实测窗口 1920×1152、页面 1920×1009、dpr 1.5）。若写成固定 viewport（如 1280×900），
  不只是页面被锁死，`devicePixelRatio` 还会被压成 1 —— 窗口最大化后整体比例就是错的。
- 抓不到时的兜底：页面上「手动导入」——把商品页源码或整页文本粘进去，或直接拖
  `.html/.md/.txt` 文件进去，**离线也能解析**；点「载入示例」可离线走完整流程。
- 想在工具窗口直接就**不用登录/过验证码**：先完全退出 Chrome，双击 `import-chrome-login.cmd`，
  它会把你在日常 Chrome 里的 1688 登录态（cookie）复制到工具的专属浏览器目录
  （新版 Chrome 的 cookie 库在 `<配置>\Network\Cookies`，脚本已按这个路径复制）。
  导入后第一次抓取会把它一并存进 `.chrome-cookies.json`，之后就一直沿用。
  注意：**正在使用的那个配置的 Cookies 文件被 Chrome 独占锁着，导不出来**，
  所以必须先退出 Chrome；脚本会自动识别你最近使用的那套配置（Default / Profile 1 …）。
  撤销：删掉 `.chrome-profile` 目录。
- **登录态是敏感文件**：服务监听 `0.0.0.0`，所以 `server.py` 把一切以 `.` 开头的
  隐藏文件/目录都挡成 403（`/.chrome-cookies.json`、`/.chrome-profile/…` 都取不到）。
  加新文件时注意别用「不带点的名字」放密钥。
- **注意**：抓取会在**本机**弹出浏览器窗口，即局域网用户也能触发本机弹窗。
  不希望这样就在 `server.py` 里加 `ALLOW_REMOTE_FETCH=0` 环境变量（或在启动脚本里 set），
  此时只有 127.0.0.1 能发起抓取；页面浏览和计算不受影响。

## 6. 定价口径（与「跨境定价计算器」完全一致）

```
K（折扣系数） = (1 − 还价%) × (1 − 折扣%)        ← 默认 20% / 15% → 0.68
拿货成本      = 拿货价 × 件数 + 配件成本
运费          = 拿货成本 × 运费率%               ← 默认 10%，固定金额，不随定价浮动
总成本        = 拿货成本 + 运费
定价          = 总成本 ÷ [K × (1 − 毛利率)]      ← 默认毛利率 33%，口径＝利润 ÷ 实际到手价
到手价        = 定价 × K
单件利润      = (到手价 − 总成本) ÷ 件数
欧元价        = 定价 ÷ 汇率（默认 7.8，按当天汇率改）
```

**「件数」怎么算（踩过坑，别改回去）**：一行的件数 = **同一规格维度内各值相加、不同维度之间相乘**。

```
双规格（颜色 × 尺码）：一双 = 颜色 1 件 × 尺码 1 件 = 1 件     ← 不是 1+1=2 件
2 色混搭 × 1 码     = 2 × 1 = 2 件
2 色 × 2 码         = 2 × 2 = 4 件
值名自带件数（5片装）= 5 件；5片装 × 2 色 = 10 件
```

把一行用到的规格值**直接相加**会让双规格商品上「一双鞋」变成两件：成本 11.5 → 23、定价 27.77 → 55.53，
整张表的价都翻倍（用户报的「件数为什么翻倍了」就是这个）。实现见 `app.js` 的 `naturalPcsOf()`（按维度分组相乘）。
AI 档同理：一件装行必须是「每个可见规格维度各取一个值」，只有这种行才算覆盖了那个规格值 ——
否则模型会顺手把基础行改成多件装来凑覆盖，整张表就没有一件装可上架了。

**低价兜底（最新口径）**：

```
只要「任一规格」的定价 < 阈值（默认 ¥3）  →  所有规格的定价统一 +加价（默认 ¥3）
```

- 注意是**整单统一加**，不是只加触发的那几个规格：原定价 0.82 / 7.39 会一起变成 3.82 / 10.39。
- 加完之后**到手价、单件利润、毛利率、欧元价都按加价后的定价重算**（所以触发兜底时，
  表格里的毛利率会明显高于目标 33% —— 兜底是"上架价下限"，不是毛利规则）。
- 参数区可改「低价兜底阈值 / 低价兜底加价」，填 `0` 即关闭；表头上方会写明是否触发、
  触发时低于阈值的规格有几个。CSV 里有一列 `低价兜底(元)` 记录每行加了多少。

- **拿货价默认取「规格标价」**：1688 规格弹层里每个颜色旁边、与库存成对出现的那个价
  （本商品 = 每色 ¥0.34）。活动价/混批价作为备选档位，页面上点一下即可切换。
- **值名自带件数时按整包算**：`灰色30cm*30cm*5片装` 这种值的标价是**整包 5 件**的价（¥11.5），
  所以那行的件数取 5、每件成本 = 11.5 ÷ 5 = 2.30、成本合计仍是 11.5（不会再被件数乘一遍 —— 
  曾经这样乘出过 25 倍错价）。`10片装` 同理（件数 10、成本 23）。件数不是整包的整数倍时按整包取整。
- **按规格组合的价（重要）**：多规格商品的价格常常**每个组合都不一样**（黄色【小花豹】18.41、小熊-情侣款 11.35），
  而页面正文里只渲染**默认选中那一个组合**的价，其它颜色的价根本不出现 —— 只按正文抓，表里就会「每行一个价」。
  所以抓取时会读页面内嵌的 `skuInfoMap`（每个组合的 price / discountPrice / canBookCount），
  解析时折成 `prod.skuPrices`：**每一行按它自己那组算成本**（混搭行 = 各组合价相加 ÷ 天然件数）。
  取价用 `discountPrice`（页面上的到手价），没有才用 `price`；值上的价/库存换成它在各组合里的最优值（价取最低、库存取最大）。
  读不到这份数据时一切照旧回落（不会瞎算）。商品区会显示「规格组合价 已读到 N 个组合的价」。
- **规格写在属性表里的商品**：有些页面（如 1002135913894）的规格是属性区里「颜色 / 尺码 各一整行逗号分隔的值」，
  规格弹层里只有默认那几档（尺码只列 3 档、实际 5 档），甚至值里带全角括号（`36/37（标准尺码）`）。
  解析器现在：① 带括号的值**不再**被当句子扔掉；② 往上找维度名时跳过「收藏代发」这类界面词；
  ③ 用「件重尺」表的表头当判据（`… 长(cm) … 重量(g)` 之前的列名就是维度名），把属性表/表里的值**补齐**（只补不重建）。
  单件重量也会用件重尺表里最轻的一档兜底。**这类商品组合数可能超过默认上限，表里会写明「只保留前 N 行」，
  要全量就把参数区的「规格组合上限」调大。**
- **已售罄的规格值不列入**：值自身的库存明确是 0，或值名里写着售罄/无货/缺货 → 解析层直接踢掉，
  商品区显示「已售罄未列入 …」提示（不悄悄消失）。页面没写库存的（null）一律保留 —— 不猜。
  整维都售罄时那一维不列，避免表里出现一列空规格。
- **引擎档只出真实规格行**：页面有几个规格值就几行（值 = 页面上抓到的原文，件数 = 值名自带的件数，否则 1），
  名字就是值原文（+ 子规格原文），英文名由词表翻译。**引擎不生成任何包装组合、配件款、多件装** ——
  不写「双支装/九支装/收纳盒」这类单位和组合（用户明确要求：不许写死任何单位和组合）。
  要打包、要配件、要做多件装，只能用 **DeepSeek 档**让它按真实数据自己判断（见 §9）；
  它要是编了页面上没有的**规格值**，整份计划被打回（值必须逐字来自抓取）。
  **变种怎么设计（多件装、混搭、套装、配件）是它的活，代码不干预、也不用词表去卡它的措辞。**
  改动前的老版本是「3 个原规格 + 8 个固定包装行」，已删除。
- 表格里可逐行改「件数 / 是否含配件」，只影响该行；参数区任意改动，表格与公式立刻重算。
- 导出：`导出上架表 CSV`、`导出全部公式 TXT`（每个变种的代入式子）。

## 8. 故障排查

| 现象 | 处理 |
|---|---|
| 局域网其他电脑连不上 | 先跑 `verify-autostart.cmd` 看防火墙那项；没放行就双击 `allow-lan-firewall.cmd` |
| 服务起不来 | 看 `logs\server.log`：出现「端口 8901 起不来」说明已有实例在跑；先 `stop-service.cmd` |
| 开机没自启 | `verify-autostart.cmd` 第 1 项；没找到自启项就重装 `install-autostart.cmd` |
| 抓取卡在登录/验证 | 直接在**那个常驻浏览器窗口**里处理（或看 `.last-page.png`）；抓取会自动继续，窗口不会关 |
| 那个浏览器窗口被我关了 | 不影响已保存的登录态；双击 `open-browser.cmd` 重新打开，或直接再点「读取商品」 |
| 验证做了但窗口/标签页被我来回点乱了 | 点一次「读取商品」即可：它会复用同一个链接的标签页 |
| 想确认抓取浏览器在不在跑 | http://127.0.0.1:8901/api/health 的 `browser` 字段（running / port） |
| 还是弹了新窗口（想用我自己的 Chrome） | 双击 `use-my-chrome.cmd`；若提示 Chrome 正在运行，先完全退出 Chrome 再跑一次（或 `use-my-chrome.cmd -Restart`） |
| 想确认现在用的是哪个浏览器 | http://127.0.0.1:8901/api/health 的 `browser.mode`（你自己的 Chrome / 工具浏览器） |
| 变种名/SKU 不对（例如明明是两色却叫「三色九支装」、SKU 全是一个） | 规格块有两种写法，解析器两种都认了；改完按 Ctrl+F5 强制刷新页面取新脚本，再点一次「强制重新抓」 |
| 想要「双支装 / 多件装 / 带收纳盒」这类组合行 | 引擎档不会生成（那是写死的组合，已按要求删除）。参数区「变种计划怎么排」切到 **DeepSeek 思考**，由它按真实数据判断要不要打包、打几件、要不要配件 |
| 变种名里出现「双支装 / 便携收纳盒」这类词 | 那是 **DeepSeek 设计的变种**（AI 档才有），不是我写死的模板 —— 引擎档只会出页面规格值本身。设计款占几行、怎么设计，看页面 ④ 区的那几行说明（含"已参考补充条件"） |
| DeepSeek 只把规格值抄了一遍、没有差异化变种 | 提示词要求了「至少 3~5 行设计款（多件装/混搭/大包装/套装）」，它偶尔仍会偷懒：再点一次「让 DeepSeek 排一版变种」换一版，或在补充条件里写「要有 3 件装和 5 色混搭」 |
| ④ 列表一开始是空的 | 这是设计：没抓到商品不预生成任何规格，也不留假的默认拿货价。点「读取商品」或「载入示例」后才会按真实数据生成 |
| 表头列名不是「颜色规格」 | 也是设计：列名 = 页面上的规格维度标签（颜色/尺码/型号…），父规格、子规格各一列，全是动态的 |
| 商品有颜色+尺码，行数很多 | 按维度组合生成（父规格计划 × 子规格值），默认最多 36 行（参数区「变种条数上限」可调，1~120，改完即时生效），超出会在提示里写明「只保留前 N 行」 |
| 表头出现「父规格 / 子规格」两列 | 页面上的规格值是组合值（形如 `【英文版.欧规】紫色全自动32mm`）：整串原样拆成两列显示，不会交叉生成页面没有的组合 |
| SKU 里的 `S1 / S2…` 是什么 | 页面没给规格编码时，按**页面上规格值出现的顺序**编号（S1 第一个值）；页面给了编码（如 `C1Y1P`）就优先用页面的 |
| 英文名那格标黄带 ⚑ | 词表里没有收录这个词，英文名里还留着中文（不瞎翻译）。在 `app.js` 的 `EN_WORDS` 里加一行中英对照即可，或直接在导出的表里改 |
| 抓取老是判「等你验证」 | 说明地址已经跳到验证/登录页（这是防假数据的设计）；在窗口里过掉验证后它会自动继续 |
| 双规格商品（颜色 + 尺码）只出现一列 | 1688 常把「价+库存」只挂在最后一个维度上（颜色没有价、尺码才有）。已在 2026-09-27 修好：以有价格那一维为锚，向上把整块值收进来。老缓存要点「强制重新抓」 |
| 表格列太多 / 只想看前两级规格 | 参数区「规格列上限」（默认 3，可调 1~3）；被藏起来的维度不会丢，调回去还在，提示里会写明还有几级没显示 |
| 变种行数被截断 | 「真实规格组合」永远排在最前面（先丢包装组合），提示里会写明「本来 N 行」；上限 = 参数区「变种条数上限」（默认 36，可调 1~120）：**AI 排计划的行数上限（maxRows）和表格截断用的是同一个值**，不是写死的 36 |
| 拿货价不是页面上的新人价/到手价 | 这是按口径来的：默认取**规格标价**；新人价、首件预估到手价归到「活动价」，推荐位的价格（其他商品）已过滤掉 |
| 表格里「毛利率」列怎么不是 33% | 那一列算的是每行的**实际达成值**。最常见原因是**低价兜底**触发（任一规格定价 < ¥3 → 全单 +¥3）：成本很低的商品（如 0.43 元/片）会整体抬高毛利率（④ 区提示里会写明「低价兜底已触发…」）。参数区「低价兜底阈值/加价」改成 0 即可关闭；另外四舍五入会显示成 32.9/33.1 这种小抖动，属正常 |
| 每个规格的拿货价不一样（单片 2.12 / 5片装 11.5 / 10片装 23） | 1688 常见写法：一个维度里每个值各自带价。表格里**每行用自己规格的标价**算成本（不是全部乘一个价），拿货价框里默认填**最低那一档**（单件出货成本）。想全部统一用一个价，把参数区「成本价怎么取」切成"全部用上面那个拿货价" |
| 值名里自带件数（`灰色30cm*30cm*5片装`、`10片装`） | 这种值的标价是**整包的价**（11.5 = 那 5 件的钱），所以：件数直接取整包（5 / 10）、名字不再多叠一个「5 支装」、SKU 的件数段是 `-5P / -10P`、每件成本 = 整包价 ÷ 件数（2.30）。拿「5片装」去拼双支装/囤货装这类包装行会被排除（否则算出「半包」）。**曾出现过整包价又被乘一遍件数的 25 倍错价，已修** |
| 英文名里出现「5片装」这类中文并被标黄 | 打包写法现在会自动转英文（`5片装` → `5-Piece Pack`、`3件套` → `3-Piece Set`），并补了 深灰/浅灰/深蓝/砖红/咖啡色/深绿/浅绿 等颜色词 |
| 点了档位按钮后各行的成本都变成同一个数 | 这是有意的：点档位＝明确要用那个价 → 自动切成"统一拿货价"。想改回来把下拉切回"按各规格自己的标价"即可（新抓一个商品会自动切回默认） |
| 每次点「读取商品」都会重新读页面 | 这是要求的行为：**每次抓取都强制清空该链接的缓存**，不会再拿 30 分钟前的旧价给你。两次真抓之间仍留 45 秒冷却（对 1688 太密会招保护验证） |
| 想让它「动脑子」排变种（挑组合/件数/英文名） | 参数区「变种计划怎么排」切成 **DeepSeek 思考**，或直接点「让 DeepSeek 排一版变种」；细节与密钥配置见 §9 |
| 点「读取商品」干等很久然后失败 / 「抓不到浏览器」 | 先看 ① 区域那行**抓取浏览器**状态：<br>· `✅ …可用` = 正常；<br>· `⚠️ 端口开着但连不上` = 那个浏览器实例**僵死**了（端口在听、调试协议不答话）—— 点它旁边的 **「重启抓取浏览器」** 就能清掉重开；<br>· 用的是「你自己的 Chrome」但调试端口不答话 → 完全退出 Chrome，再双击一次 `use-my-chrome.cmd`（工具**不会**去重启你的浏览器）<br>另外：每个任务都留了 `logs/job-<任务号>.log`（逐步状态 + 退出码），失败时页面会把最后几行直接贴出来 |
| 抓取失败但页面只显示「正在准备抓取浏览器…」就没下文了 | 老版本的坑：进程被强杀时没有任何输出，页面只能留着你上一步的提示。现在会明确写「抓取进程中途退出了（退出码 N），最后一步是…」并指向任务日志 |
| 工具浏览器窗口里堆了很多 1688 标签页 | 抓取**故意不复用**已有标签页（复用会重新导航你正在看的页面），所以每次抓取都会新开一个。窗口关了不影响下一次自动开；想清干净双击 `close-browser.cmd` |
| 点了 DeepSeek 报「没配密钥」 | 在项目根建 `.ai.json`（点开头的文件不会被静态服务读走），或设环境变量 `DEEPSEEK_API_KEY`；见 §9 |
| DeepSeek 排的计划没被采用（提示里说「已回落」） | 页面上会写原因：编造了页面上没有的规格值 / 漏了规格值又不说理由 / 超时或限流。直接再点一次即可；连续失败就先用引擎规则 |
| 页面能开但抓取按钮报错 | 打开 http://127.0.0.1:8901/api/health 看 `node`/`playwright` 是否 false |
| 改了端口 | 设环境变量 `PORT`（同时要改防火墙规则和自启快捷方式参数） |

## 9. DeepSeek 排变种（可选增强）

**它负责什么**：**设计变种规格** —— 覆盖每个规格值之后，再排出多件装 / 混搭 / 大包装 / 套装这些真正有差异的卖法
（提示词要求至少 3~5 行设计款；组合、件数、"一行里放几个值"全由它判断，代码里没有任何固定组合表），
外加 **中文变种名 + 英文变种名**，以及哪些值这次不上架（要写理由）。
⚠️ 别把"不许写死"做成"不许设计"：代码不该有固定组合表，但也不该用词表去卡模型的措辞 —— 那样 AI 档会退化成
把页面规格抄一遍（用户当场指出过：「你只是让deepseek给你重新排序？我需要的是变种规格」）。

**名字是谁写的**（这一栏以前是引擎模板拼的，被问过「是不是写死了」）：

- AI 档：中文名与英文名都请模型写（中文名约束：≤40 字、必须带上本行真实规格值原文或款数、含配件的要点出配件、不许写价格）。
- 模型没给中文名，或给了带价格/超长的 → **只把这一栏丢成空**，由引擎模板兜底（那行本身照旧保留）。
- 页面 ④ 区与导出的公式 TXT 里都会写明：**中文名 N 行来自 DeepSeek、M 行回落引擎模板**（按表里真实渲染出的行数）。
- 引擎规则档：中文名/英文名一律由引擎按抓取数据 + 词表生成（不联网也能用）。

**它不负责什么**（这几条是硬约束，写在 `ai-plan.cjs` 里）：

- **不算钱**：价格、成本、运费、利润、欧元价一律由本地引擎（`app.js`）算。AI 就算硬塞 price/cost 字段也会被剥掉。
- **不许编造规格值**：只能逐字使用页面上抓到的值，出现数据里没有的值 → 整份计划作废。
- **不许静默丢规格**：每个值都得有「原规格」行，或者进 skipped 并写理由；漏了 → 带着纠错提示重问一次，还漏就作废。
- **行数封顶**：跟随参数区「变种行数上限」，超了会写明「只保留前 N 行」。

**补充条件（文本框）**：按钮右边那个「给 DeepSeek 的补充条件」是自由文本，跟规格数据一起发过去当**参考条件**：

- 例：`主推 2 件装和 4 件装，各色都上；只做深色系；名字尽量短；那个清仓随机款先不上架`。
- 它进的是请求数据（`params.note` → `extra_conditions`），**不进系统提示词** —— 所以它压不翻硬规矩：
  规格值仍只能逐字来自抓取、不许给价格、不许自己造单位/配件词；做不到的要求模型会忽略并写一句原因。
- 内容存浏览器本地，刷新/换商品都不丢；去标签、压空白、最多 500 字。
- **只在 DeepSeek 档生效**：引擎档不联网，没有"参考条件"这回事（文本框下面那行会提醒）。
- 每次生成后，④ 区会回显这次用到的补充条件（`参数：… ｜ 补充条件：…` 也会写进导出的公式 TXT），
  这样"它到底有没有按我说的排"是可查的。

**怎么用**：参数区「变种计划怎么排」→ 选 `DeepSeek 思考`（或直接点「让 DeepSeek 排一版变种」）。
选了这一档，**读完商品会自动排一版**；「重新生成规格」在这一档下 = 再排一版（换一版计划）。提示区会写：模型、耗时、跳过了哪些值及理由。

**失败怎么办**：任何失败（没配密钥 / 超时 120 秒 / 限流 / 计划两次都没通过校验）都会**自动回落到引擎规则**，表格照常可用，红色提示写明原因。

**密钥怎么配**（二选一）：

1. 项目根建 `.ai.json`：`{"baseUrl":"https://api.deepseek.com","model":"deepseek-flash","apiKey":"sk-…"}`（点开头的文件被静态服务 403 挡住，不会被局域网读走）
2. 环境变量 `AI_BASE_URL` / `AI_MODEL` / `DEEPSEEK_API_KEY`（优先级高于文件）

密钥只在**服务端**使用：浏览器只会看到「排了几行、哪几行、耗时多少」，请求体返回体里都不含密钥。

**模型选择**：默认 `deepseek-flash`（实测一版 4~25 秒，计划完整度最好）；`deepseek-v4-pro` 更啰嗦也更慢。改 `.ai.json` 的 `model` 即可。
调用参数上有个坑：必须显式 `thinking:{type:"disabled"}` 且 `max_tokens` 给够，否则接口 HTTP 200 但内容为空。

**接口**：`POST /api/ai-plan`，体为 `{product, params:{maxDims, maxRows}}`；`/api/health` 里的 `ai` 字段表示密钥是否已配好。

**注意**：表里只显示前 N 级规格（参数区「规格列上限」），所以**只有这几级会交给 AI**，被藏起来的维度不进计划（否则行会撞车）。

## 商品材质（① 商品信息区）

- 抓取页面上「鞋底材质 / 鞋面材质 / 内里材质 / 鞋垫材质 / 主面料成分」这类属性行，逐字显示在 ① 区「材质」一项上。
- 页面上有两种排版，各自读法不同：属性表（带制表符）是「标签在下、值在下一行」；详情区纯文本是「值在上一行、标签在下」。
  同名以属性表为准，纯文本当兜底；最多显示 4 项。
- 页面底部 SEO 说明里也含「材质」字样（长句），整行不等于标签就不算；没有证据就不显示这一项（不编）。
- 回归：test_parse 用 4 个真实夹具断言到具体值（含「材质=木塑」这种单独成行的写法）。

## 尺寸信息（① 商品信息区，与「材质」并列）

- 两个来源都读，全部来自页面：
  - **件重尺表**：表头含「长(cm) 宽(cm) 高(cm) 体积(cm³)」，按**表头列名定位**取值（有的表前面还有颜色/尺码两列）。
    逐规格一行，规格不同就把每一项显示成 min~max 区间；显示为「长 27.5–32 · 宽 24.5–27 · 高 9–14 cm」。
  - **属性行「尺寸」**：如「尺寸 → 7*7.5」，逐字保留，显示为「页面标 7*7.5」。
- 两个都没有 → ① 区不显示这一项（不编）。
- 回归：test_parse 断言区间值（27.5–32 / 24.5–27 / 9–14）、无前置列的表（8/7/2）、属性行原文（7*7.5）、
  以及「页面没有 → null」；test_page 断言 ① 区渲染与「没有就不显示」。

## 点 DeepSeek 后追加的「组合套装款」（用户指定）

点了「让 DeepSeek 排一版变种」之后，除了它自己排的行，还会**确定性追加**：1 / 2 / 3 / 6 / 12 件装 + 多色混搭。

- 挂在这个页面**默认规格值**上（第一个颜色的第一个尺码，即页面默认选中的组合）；多色混搭 = 前 3 个单件颜色各 1 件。
- 追加款合成的是「计划行同构」的行，走**同一个行构造循环** —— 成本/运费/定价、件数对齐、SKU 口径与 AI 行完全一致，
  价格永远由本地引擎算；混搭只用**单件值**（值名自带件数的整包值不参与，避免 1+5+10 混成 16 件）。
- 撞已有 SKU 的追加款自动跳过（例如 AI 已排了同值的单品行，1 件装就不重复加）；追加款在设计款里排最前，
  行数封顶时不会被 AI 的其他设计款挤掉。
- 只在 DeepSeek 档出现；引擎档不追加（那是规则档，不加用户没要求的东西）。
- test_app / test_page 各有一条「追加款在表里」+「SKU 唯一」的断言盯着。

## 补充条件里的「名字不超过 N 个字」= 硬约束（不是许愿）

以前补充条件只是「参考条件」发给模型，做不到就忽略 —— 用户报过「在文字框里写了不能超过 9 个字，生成出来还是超」。
现在：`ai-plan.cjs` 会从补充条件里**解析**这类可校验的要求，当硬规则逐行量。

- 认得的写法：`不超过/不能超过/超过/少于/小于/至多/最多/限/≤/<=/≦ + N + 字`、`N个字以内/以下/之内`
  （例：「规格名称不能超过9个字」「名字9个字以内」）。只量中文名（nameCn），英文名按字符数算没意义。
- 超了整份打回重排，报错点名到行：「第 14 行「树莓粉 42/43 两件装」13 字」，并给出压短办法
  （丢件数后缀、丢括号说明；值本身撑超的按最短可区分写法）。
- 硬规则全过、**只**差名字长度的那一版会兜底照排（页面备注写明哪几行没压到）——值本身就有 10 字
  （如「白色【3411牛角】」）时压不进 9 字是物理限制，整份丢空比照排 + 说明更糟。
- **追加的组合套装款也守这条**：名字逐级压缩 `柠檬黄 36/37（标准尺码） 2件装` → `柠檬黄36/37×2` → `柠檬黄×2`
  （名字可以简写，计划里的值仍是逐字原文）。
## 深坑：名字里的「×N」是每款数量 —— 件数校验的「误杀死锁」（已修）

用户报障：同一份计划连打回三次 ——「第 7 行：你列的规格值本身就有 5 件…但件数写的是 2」。

- 根因不在模型：它给混搭套装起名「1.5cm×2+2.5cm×2+3.5cm×1 5双套装」，`×2` 是**每款数量**；
  旧解析器抓**第一个 ×2** 当总件数，把模型写对的 5 覆盖成 2 → 校验以「值组合数 5」打回 →
  下一轮模型仍这么写名字、又被覆盖成 2 —— **同一处改写卡死每一轮，怎么写都过不了**。
- 修复（ai-plan.cjs）：
  - 件数解析**收集全部候选**：带「件装/双(套)装/套装/Pack/Pairs」后缀的**唯一值**优先；裸 `×N`
    只有全名里只出现一个数字时才信；多个不同数字（多半在描述每款数量）→ 不猜、不覆盖。
  - 名字数字与值组合数冲突时，**谁跟「天然件数」对得上就听谁的**；字段对、名字旧 → 保留字段，
    并把名字里过时的总件数写法同步改掉（`2双装` → `5双装`，页面备注说明）。
  - 裸 `×N` **绝不改写**（「×2+×2+×2」里挑一个改成别的数字＝把名字写坏）；值原文自带的写法
    （值叫「…5片装」）不动。注意「N双套装」≠「N双装」，后缀表里要显式含「双套装」。
- 回归：test_ai 新增 6 条（准确形状一轮通过、过时数字按值校正、第二轮改对后不再卡死、裸 ×N 原样保留）；
  真跑该商品 3 次全部一轮通过；全量 484 项全绿。
## 抓取解析的坑：「0 个规格维度」的三种真因（791436406391 报障）

用户报「这条链接 deepseek 不工作，报错『还没有规格数据』」——问题在**抓取解析**：页面抓到了，但规格维度是 0。
排查入口：抓取脚本会落 `.last-page.txt`（页面原文，异常时还有 `.last-page.png`），拿真文本直接离线复现解析。
同一条链接上三种真因可以同时存在（都已修，见 parse-1688.js）：

1. **「纯数字不是规格值」一刀切**：尺码就是 36~45 这种纯数字，旧过滤器把整组丢光 → 带价+库存的值全没了。
   现在只挡「不像规格值的数字」：0 开头 / 点开头（`0.3`、`.10` 是价格换行拆分残留）、≥4 位（`89602`）；
   放行 1~3 位整数和半码（`36.5`）。`isBareValueLine` 的对称规则同步改了。
2. **标签行被备注粘住**：「尺码按包起批，每包5双」超过 8 字上限被判「没有独立标签」→ 尺码值会并进颜色维度。
   现在这类 9~20 字的行会取开头的维度词当标签（≤8 字短行行为不变）。
3. **件重尺表头没有「长(cm)」列**（如 `颜色 尺码 重量(g)`）：整张表被跳过、重量也丢。
   现在表头上方有「件重尺」路标、且表头没有任何测量列时，改用「重量(g)」列当锚读表；
   「长(cm) 排首位」的纯尺寸表仍然跳过（曾把 长/宽/高/体积 认成规格维度的那条底线）。

## 抓取解析的坑：整单价格读错（1070076236814 报障「真实价格抓错了」）

症状：表里所有行成本都是 0.20（或别的怪数字），真实价其实是 ¥12.8。这不是一个 bug，是四个叠在一起：

1. **规格值名里带「，」被当句子丢**：尺码名是「M【适合尺码37-38】…拍大一码，靴子拍大两码」，旧过滤器连「，」都挡
   → 4 个尺码全部进不了「带价规格值」名单 → 价格 12.8 挂不上 → 整单退回无价表值。
   现在只有 ¥/￥ 与句末标点才判「不是值」。
2. **逗号拆分歧义**：同一行同时有「,」和「，」时按「,」拆（「，」留给值内部）；只出现一种才按它拆。
   早先一律按 [,，] 拆，把「…拍大一码，靴子拍大两码」劈成两个假规格值。
3. **「+¥0.2/0.3/0.4…」是定制/包装加价项**，不是价格档位——现在一律不进档位；
   推荐区（同款推荐/猜你喜欢…）里别家商品的价格靠「规格块结束位置」往后的 zone 切掉。
4. **主价紧邻处就有「已售2900+套」和「对比」按钮**，旧的噪声窗口 (±35) 把它们当推荐位特征 → 把主价 12.80 也误杀了
   → 价格档位整段丢空 → 拿货价错成别的价。现在这两个词不再当噪声（推荐卡的价格由「紧跟 售/已售+数字」与 zone 兜住）；
   另修：「商家代发热度/代发商家榜」这类统计文案不许当「代发价」标签；pre 窗口撞到上一个价格就截断（别把上一个价的「首件预估」带进来）。

回归：fixture `fixtures/offer-1070076236814.txt` + test_parse 12 条断言；真链路 = 从本机服务重抓：
颜色 4 / 规格 4（各带 12.8+库存）→ specPrice 12.8 → 拿货价 12.8 → 档位只有 [12.8]。

## 单位来自页面数据（双/件/卷/对…），不再一律写「件」（725837664482 报障）

- 解析层新增单位识别：从「1双起批 / 每包5双 / 库存879587双 / 100-999双 / ≥1000双 / 已售…双」投票选出；
  推荐位的「已售…」只用第一条、规格弹层（同一行带 ¥ 的单色价）排除；没有任何证据就回落「件」，不编造。
- 名称三处全部改用页面单位：① DeepSeek 提示词带 unit_rule（名字/kind 写「N双装」）；
  ② 服务端兜底改写（模型仍写「6件装」→ 自动改成「6双装」并在备注里说明；值原文带「件装」的行不动）；
  ③ 前端套装梯与多色混搭（1/2/3/6/12 双装、各1双）。

## 「件数必须是 N 的整数倍」死锁：值名里的中文数字（1059815945700 报障）

- 值「SCN376-六个(10*10)」的「六个」是中文数字：旧件数解析只认阿拉伯数字 → 把它当 1 件。
